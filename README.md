# ECHOES

> **Active client:** the React Native + Expo app in [`mobile/`](mobile/) is the current client (see "Run the Expo app" below and `status.md`). The Flutter app described in the rest of this file is the legacy implementation.

ECHOES is a Flutter/Firebase beta for place-based memories: users attach photos and text to locations, places develop emotional aura summaries, and custodians can preserve memory spaces over time.

## Beta Status

- Flutter app, Firebase repositories, local repositories, Cloud Functions, Firestore rules, notification requests, crash reporting, analytics, caching, privacy paths, communities, custodianship transfer, and AR fallback/prototype flows are implemented.
- Local validation currently covers analyzer checks, unit/widget tests, beta integration tests, Cloud Functions tests, and Firestore rules tests.
- Remaining beta gate items require hardware or emulator sessions: Android/iOS smoke tests, permission prompts, offline/manual retry checks, ARCore/non-AR behavior, and target-device performance measurement.

## Run the Expo app

The app lives in `mobile/` (React Native + Expo SDK 58). Choose a backend with `EXPO_PUBLIC_BACKEND` (copy `mobile/.env.example` to `mobile/.env`):

- **memory** (default): seeded demo data, no network. Sign in with `demo@echoes.app` / `echoes-demo`. Demo mode pins your location to the demo neighbourhood (Bengaluru) so the seeded map is never empty, wherever you are.
- **emulator**: Firebase emulators. Start them from the repo root with
  `npx firebase emulators:start --project demo-echoes --only auth,firestore,storage,functions`,
  then set `EXPO_PUBLIC_BACKEND=emulator`. On a physical phone also set `EXPO_PUBLIC_EMULATOR_HOST` to your PC's LAN IP.
  Emulators bind to localhost only by default. For a physical phone, use the opt-in LAN config instead:
  `npx firebase --config firebase.lan.json emulators:start --project demo-echoes --only auth,firestore,storage,functions`.
  **Warning:** `firebase.lan.json` binds the emulators to `0.0.0.0`, exposing them (unauthenticated, with open demo data) to everyone on your network. Use it only on a trusted network, and allow ports 9099, 8080, 9199 and 5001 through your firewall.
  `firebase.lan.json` also loads `firestore.lan.rules`, the only rules that accept Storage emulator media URLs on private-LAN hosts (the default `firestore.rules` accepts only `127.0.0.1`/`localhost`, see Security rules notes).
  On the Android emulator either use the LAN config with `EXPO_PUBLIC_EMULATOR_HOST=10.0.2.2` (the emulator's alias for the host PC), or keep the default localhost-only emulators and forward the ports, leaving `EXPO_PUBLIC_EMULATOR_HOST` unset:
  `adb reverse tcp:9099 tcp:9099`, `adb reverse tcp:8080 tcp:8080`, `adb reverse tcp:9199 tcp:9199`, `adb reverse tcp:5001 tcp:5001` (this also works for a USB-connected Android phone).
- **firebase**: a real project. Set `EXPO_PUBLIC_BACKEND=firebase` plus all `EXPO_PUBLIC_FIREBASE_*` keys from `.env.example`; a missing key fails at startup with `Missing EXPO_PUBLIC_FIREBASE_<KEY>`.

Expo app features: map and places, add memories with photos and 60 s voice notes, memory detail with edit, delete and restore (Recently deleted keeps items 30 days), an offline outbox that retries saves, profile with default privacy, and account deletion with re-authentication.

Expo Go steps:

```bash
cd mobile
npm install
npx expo start
```

Scan the QR code with Expo Go (Android) or the Camera app (iOS). Restart with `npx expo start -c` after changing `.env`.

The repo configures the Firestore emulator on port `8080` in `firebase.json`. To run emulator-backed checks:

```powershell
npx firebase emulators:start --only firestore,storage
```

In another terminal:

```powershell
npm test --prefix rules_test
```

For a one-shot rules test, prefer:

```powershell
npx firebase emulators:exec --only firestore,storage "npm test --prefix rules_test"
```

`firebase.json` also configures the Auth (`9099`), Storage (`9199`) and Functions (`5001`) emulators. The Expo app's Firestore backend is verified against the backend contract suites (`mobile/test/contracts`) under the real `firestore.rules`/`storage.rules`. All mobile emulator commands use the demo project id `demo-echoes` (no real Firebase project needed); run from the repo root:

```powershell
npx firebase emulators:exec --project demo-echoes --only auth,firestore,storage,functions "npm --prefix mobile run test:emulator"
```

### Security rules notes

- Soft-delete stamps are server time (ruling R13): `deletedAt`/`updatedAt` must equal `request.time` on a soft delete, and a restore must clear `deletedAt` within 30 days of it. Clients write `serverTimestamp()`.
- Memory `sentiment` must be numeric (`compound` in [-1, 1]; `positive`/`neutral`/`negative` in [0, 1]); `onMemoryWritten` also clamps it.
- `firestore.rules` and `firestore.lan.rules` are **generated**; edit `firestore.rules.template` and run `node scripts/build-rules.js` (no dependencies), then commit all three. `rules_test/build-rules.test.js` fails if the generated files are stale. The committed files pin the emulator bucket `demo-echoes.appspot.com`; deploy with `npm run deploy:rules -- --project <project-id>` from the repo root, with `FIREBASE_STORAGE_BUCKET` set to the exact bucket name from the Firebase console (e.g. `<project>.firebasestorage.app`; PowerShell: `$env:FIREBASE_STORAGE_BUCKET='<bucket>'`). It refuses to run without that variable, regenerates the rules for that bucket and deploys `firestore:rules,storage`. Do not commit that build (run `npm run build:rules` afterwards to restore the committed files).
- Memory `imageUrl`/`audioUrl` must be null or a Storage download URL in the pinned bucket for the author's own folder (`memory-images%2F<uid>%2F…`, `memory-audio%2F<uid>%2F…`). `firestore.rules` accepts `https://firebasestorage.googleapis.com` and the Storage emulator at `http://(127.0.0.1|localhost):9199`; `firestore.lan.rules` (used only by `firebase.lan.json`) additionally accepts `10.0.2.2` and private-LAN IPv4 hosts on port 9199 (ruling R18).
- Plan 3 (ADR-0007/0008): `communities` (and `members`), `transfers`, `institutions` and `places` updates are server-only (callables/triggers); clients only read them, and only create empty places they look after. `reports`, `rateLimits` and `notificationRequests` are closed to clients. `publicProfiles/{uid}` is readable by any signed-in user and written only by its owner (`displayName` 2–40 code points, `displayNameLower`, `updatedAt`). `users/{uid}/notifications` are owner-read and the owner may only set `readAt`; `users/{uid}/blocks` are owner-only `{ createdAt }`.
- Memory writes: `taggedUserIds` is a list of at most 20 (ruling R24, `MAX_TAGS`), and `privacy: 'community'` requires a `communityId` the author is a member of (create and edit). Client-created places must be named `Memory Place` with numeric coordinates, a string geohash and an empty aura.
- Memories carry `moderation` (`null`, or `'hidden'` set by the server after 3 reports). New memories must write `moderation: null`; clients can never change it or `flags`. Hidden memories are readable only by their author, so non-own list queries must filter `where('moderation', '==', null)`. A moderator un-hides a memory by setting `moderation` to `null` (not by deleting the field).
- `users/{uid}` (holds the email) is readable only by its owner. Storage files are readable through the SDK only by their owner; viewers load media through the token download URLs stored on memory docs.

## Beta Smoke Checklist

Use this checklist on Android first, then iOS if available:

- Sign up and sign in.
- Grant or deny location permission and confirm the map state is understandable.
- Add a text memory with location captured.
- Add a gallery or camera image memory.
- Open a place detail sheet and memory detail sheet.
- Edit memory text/privacy and soft-delete a memory.
- Join a community and create a community-scoped memory.
- Initiate and accept a custodianship transfer.
- Toggle notification permission settings.
- Launch AR on an ARCore device and on a non-AR device to verify fallback.
- Enable airplane mode after loading nearby content and verify cached browsing behavior.
- Retry a failed image upload after network returns.

Record performance on a target mid-range Android device:

- App launch under 3 seconds.
- Memory/place load under 2 seconds.
- Location update under 1 second.
- AR mode at 30 FPS or better.
